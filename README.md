# Бэклог

Игры, сериалы, кино и аниме, до которых хочется добраться. Личный и общий на двоих бэклог: вход через Google по приглашению, данные в Supabase, работает офлайн и ставится на экран «Домой».

Адрес: https://ledoksi.github.io/backlog/

## Как устроено

- `app/` — приложение: React 19, TypeScript, Vite, Zustand, Motion, PWA через `vite-plugin-pwa`.
  - `src/lib/` — чистая логика без React: слаги и id, фильтры и сортировка, статус по отмеченным сезонам, валидация, синхронизация, поиск по внешним источникам.
  - `src/data/` — сторы и связь с Supabase: тайтлы (`titlesStore.ts`), синхронизация (`syncEngine.ts`), сессия, фильтры, итоги.
  - `src/screens/` — экраны: вход, бэклог, панель тайтла, редактирование, быстрое добавление, итоги, профиль, друзья, страница друга, приватность.
  - `src/ui/` — общие компоненты, `src/design/` — токены и темы.
  - `retired-v2/sw.js` — воркер по старому адресу `/backlog/v2/sw.js`: снимает старую установку v2, если она где-то осталась.
- `images/` — обложки (`images/covers/`) и иконки, публикуются по `/backlog/images/`.
- `supabase/migrations/` — схема базы по шагам. Первый файл — снимок схемы, какой её оставила v1.
- `worker/proxy.js` — CORS-прокси на Cloudflare для Steam и TMDb, выкладывается вручную через панель Cloudflare.
- `docs/superpowers/` — спеки и планы редизайна (фазы A–D), `docs/design/` — макеты.

## Данные и синхронизация

Тайтлы лежат в одной таблице `titles`, каждый на своей доске (`workspace_id`): личной или общей на двоих (`workspaces`, `workspace_members`). Профиль с ником и настройками — `profiles`. Доступ ограничен RLS: человек видит только доски, где он участник; всё о чужих досках — только через функции (см. «Друзья и приватность»). Вход — только по приглашению админа: на почту (`allowed_emails`, 30 дней) или одноразовой ссылкой (`invite_links`, 7 дней, можно привязать к почте); профиль и личную доску при первом входе создаёт `complete_signup`. Админ — строка в `admins` (сейчас Георгий), её меняют только из SQL Editor; функции приглашений начинаются с `assert_admin()`. Имя из Google не копируется.

В браузере у приложения зеркало открытой доски в `localStorage` с префиксом `bl2:`. Правка сразу пишется в зеркало и показывается, затем уходит в Supabase; без сети она ждёт в очереди и отправляется при появлении сети. При запуске очередь отправляется до того, как скачивается общее состояние. Чужие правки приходят через realtime; пока открыта панель или форма, перерисовка откладывается.

Ключи в `app/src/config.ts` (Supabase publishable, TMDb, RAWG) — клиентские: браузер обязан предъявлять их сам, данные защищены RLS.

## Друзья и приватность

Соцчасть (фаза D редизайна) живёт в Supabase: таблицы `friendships`, `friend_requests`, `invite_links`, `activity_events` и функции-RPC в `supabase/migrations/20261020*.sql`. Прямого доступа к чужим тайтлам нет: всё, что человек видит о другом, идёт через одну функцию `visible_titles_for(владелец, зритель)`.

- По умолчанию всё закрыто: доски `private`, в лидерборде никого нет. Видимость доски («Только я / Друзья / Все в Бэклоге») и четыре переключателя (лидерборд, лента, совпадения, поиск по нику) — в «Профиль → Приватность».
- Скрытый тайтл («Скрыть от друзей» в панели тайтла) не виден никому, кроме участников той же доски: ни на полке, ни в ленте, ни в совпадениях, ни в совпадении вкусов.
- Друзья взаимные: заявка по нику. Ссылки-приглашения (`#f/<токен>`) делает только админ («Профиль → Пригласить в Бэклог»): новичок по ней попадает в приложение, и у него уже висит заявка от админа. Кто прошёл по ссылке, записывается в `invite_redemptions`.
- Лента: события пишет триггер на `titles` (добавил, начал, завершил, отметил сезоны), только на неприватных досках и не для скрытых тайтлов; при чтении видимость проверяется ещё раз. События старше 90 дней удаляет ночная задача `pg_cron` `bl-activity-retention`.
- Лидерборд показывает только число и только доски, которые включили участие: личная — переключателем «Лидерборд» её владельца, общая — своим переключателем «Общая доска в лидерах», который может менять любой участник. Личная и общая доска — разные строки, тайтлы не смешиваются.
- Копировать тайтл можно только с полки друга («Добавить к себе» в его профиле) и только то, что друг тебе показывает; между своими досками копирования нет.
- Почта нигде не отдаётся другим людям (и её первая половина не служит именем).
- «Профиль → Данные и аккаунт»: «Как мы используем данные» (тот же лист открывается с экрана входа; текст в `app/public/data-info.json`, держать в согласии со схемой и внешними источниками) и «Удалить аккаунт» (`delete_my_account` по нику: личная доска и всё личное удаляются, общая доска остаётся второму участнику). Ночная задача `bl-stray-auth` удаляет учётки Supabase Auth без профиля старше суток.

Проверки базы — pgTAP: `supabase/tests/support/run-local.sh` поднимает локальный Postgres 16, применяет миграции, гоняет тесты и проверяет, что каждый откат из `supabase/rollbacks/` возвращает схему как была. Матрица приватности — `supabase/tests/privacy_matrix.sql`.

## Запуск и проверки

```bash
cd app
npm install
npm run dev          # http://localhost:5173/backlog/
npm test             # модульные тесты (Vitest)
npm run typecheck
npm run build && npm run budget   # сборка и бюджет JS 250 KB gzip
npm run e2e          # Playwright: телефон и компьютер, доступность, снимки экранов
```

Снимки экранов: `app/e2e/visual.spec.ts-snapshots/`. Переснять после намеренных изменений: `npx playwright test e2e/visual.spec.ts --update-snapshots`, затем просмотреть новые снимки.

## Выкладка

`.github/workflows/deploy.yml` на каждый push в `master`: тесты, сборка, сайт из `app/dist` + `images/` + воркер `retired-v2/sw.js` в `/v2/`, публикация на GitHub Pages. `ci.yml` гоняет тесты, сборку с бюджетом и e2e на каждом PR.

## Supabase: настройки вне кода

- Authentication → Providers → Google: OAuth-клиент из Google Cloud Console.
- Authentication → URL Configuration: Site URL и Redirect URLs — `https://ledoksi.github.io/backlog/`. Без полного пути сессия теряется после входа.
- Новый участник: приглашение из профиля админа в приложении. Первый вход до того, как email приглашён, создаёт пользователя без профиля — приложение покажет «не приглашён», а через сутки такую учётку удалит `bl-stray-auth`.
- Админ: `insert into public.admins (user_id) values ('<id>')` в SQL Editor.
