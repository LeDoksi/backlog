## Как читать макеты

Файлы `mockups/*.dc.html` написаны в формате Design Component: обычная HTML-разметка с инлайн-стилями, `{{…}}` подставляются из `renderVals()` в `<script type="text/x-dc">` внизу файла. Отдельно в браузере они не рендерятся (им нужна среда холста), но это точная спецификация: размеры, отступы, цвета и тексты берутся прямо из разметки. Пути к постерам уже указывают на `images/covers/` этого репозитория.

Почти у каждого экрана есть свойство `dark`: одна разметка на две темы, цвета в объекте `t` в `renderVals()` (значения совпадают с [`tokens.css`](tokens.css)). Файлы `*Dark.dc.html` подключают тот же экран с `dark = true`.

`TabBar.dc.html` и `DeskRail.dc.html` — общие компоненты, остальные экраны подключают их через `<dc-import>`.

## Известные мелочи макетов

Пользователь посмотрел макеты и решил не перерисовывать ради пары кнопок. Поправить при реализации:
- Любая кнопка или чип в одну строку (`white-space: nowrap`), подписи сокращать, а не переносить. В макетах это уже проставлено, но ширины местами впритык.
- В `ACQuickAdd` вместо постеров из поиска стоят заглушки: в приложении там реальные постеры из TMDb/Shikimori/Steam.
- Серый блок «место клавиатуры» в `ACQuickAdd` — пометка макета, не элемент интерфейса.
