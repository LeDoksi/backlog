**Goal:** Раздел «Админка» только для Георгия: люди и действия (блок, сброс ника, удаление), приглашения с лимитами, сигналы, журнал, здоровье данных, место, уведомления в Telegram.

**Architecture:** Всё в базе: таблицы админки закрыты RLS без политик, данные отдают функции `security definer`, каждая начинается с `perform assert_admin()`. **Tech Stack:** Postgres (`pg_cron`, `pg_net`, `vault`), pgTAP; React как раньше.

**Spec:** разделы 4.1–4.9.

## Global Constraints

- Ни одна функция админки не возвращает содержимое чужих досок: только числа (тайтлы, друзья, доски, байты).
- `assert_admin()` бросает `insufficient_privilege` для всех, кроме строк в `admins`. Таблицу `admins` меняют только из SQL Editor.
- Себя заблокировать, сбросить или удалить нельзя (проверка в функции).
- Удаление аккаунта требует `p_confirm_nick` равного нику человека.
- Стартовые пороги: новичков от одного за сутки > 5; тайтлов за час > 100; заявок в друзья за сутки > 20; похожие имена: `георгий`, `гоша`, `ledoksi` (без регистра, без учёта Георгия). Лимиты приглашений: 5 живых ссылок, 10 приглашённых за 30 дней.
- Лимиты тарифа: база 500 МБ, хранилище 1 ГБ, жёлтый с 70%.
- `fetch_errors` хранит 30 дней (ночная задача `pg_cron`).
- Токен бота и id чата только в Vault (`bl_tg_token`, `bl_tg_chat`).
- Каждое действие админа пишет строку в `admin_log`.

## Review Focus

1. Заблокированный с открытой вкладкой: следующий запрос к базе пуст, приложение показывает «Доступ закрыт», а не пустой бэклог с ошибками. Тест в задачах 2 и 4.
2. Общая доска, один участник заблокирован: второй участник продолжает видеть и править доску. Тест в задаче 2.
3. Удаление человека, у которого общая доска: доска остаётся второму, его тайтлы на ней остаются. Тест в задаче 2.
4. Telegram недоступен или токен неверный: событие не теряется и не шлётся бесконечно (3 попытки, потом ошибка в «Здоровье»). Тест в задаче 7.
5. Лимит приглашений: ссылка, созданная до лимита, продолжает работать; новая не создаётся с понятным текстом. Тест в задаче 3.
