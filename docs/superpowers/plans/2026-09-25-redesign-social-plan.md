# Редизайн, доски и социальные функции — план реализации (индекс)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Переписать Бэклог на React в утверждённом дизайне A+C, добавить личную и общую доску и соцфункции для узкого круга, ничего не потеряв из текущих данных и функций.

**Architecture:** Новое приложение `app/` (Vite + React + TS) живёт рядом с текущим по адресу `/backlog/v2/`, пока не догонит его по функциям на текущей схеме базы. После этого заменяет v1, и только тогда схема переходит на `titles` + доски + соцтаблицы. Всё соцчтение идёт через RPC-функции Postgres с проверкой приватности.

**Tech Stack:** React 19, TypeScript 5, Vite 7, Motion 12, Zustand 5, supabase-js 2, Phosphor Icons, Vitest 3, Playwright 1.56, Postgres (Supabase) с RLS и `pg_cron`.

**Spec:** [`docs/superpowers/specs/2026-09-25-redesign-social-design.md`](../specs/2026-09-25-redesign-social-design.md). Дизайн: [`docs/design/2026-09-25-redesign/`](../../design/2026-09-25-redesign/).

## Как устроен план

Спека описывает четыре независимые подсистемы, поэтому у каждой свой план. Каждый план даёт рабочий результат сам по себе и выкатывается отдельно.

| Порядок | Эпик в канбане | План | Итог |
|---|---|---|---|
| 1 | **BL-E5 · A. Фундамент v2** | [`2026-09-25-redesign-A-foundation.md`](2026-09-25-redesign-A-foundation.md) | v2 открывается на `/backlog/v2/`: вход, оболочка, компоненты, CI. Плюс фикс BL-26 в v1. |
| 2 | **BL-E6 · C. Редизайн ядра** | [`2026-09-25-redesign-C-core.md`](2026-09-25-redesign-C-core.md) | Все экраны бэклога в новом дизайне на текущей схеме, паритет с v1, v2 заменяет v1. Закрывает BL-25 и основную часть BL-27. |
| 3 | **BL-E7 · B. Модель данных v2 и доски** | [`2026-09-25-redesign-B-data.md`](2026-09-25-redesign-B-data.md) | Таблица `titles`, профили с ником, личная и общая доска, переключатель, внешние ID. Закрывает BL-24. |
| 4 | **BL-E8 · D. Социальщина** | [`2026-09-25-redesign-D-social.md`](2026-09-25-redesign-D-social.md) | Друзья, приватность, лента, совпадения, совпадение вкусов, лидерборд. Закрывает BL-21. |

**Уровень детализации.** План A расписан по шагам с кодом, его можно выполнять сразу. Планы C, B и D расписаны по задачам: файлы, интерфейсы, SQL целиком, ключевой код, тесты и критерии приёмки. **Перед стартом каждого из них** исполнитель заново запускает `superpowers:writing-plans` для этого подпроекта и разворачивает задачи в шаги по 2–5 минут против кода, который будет в репозитории на тот момент. Код v2 появится только после A, поэтому шаги, написанные сейчас, устарели бы.

## Global Constraints

Каждая задача любого плана неявно включает эти требования:

- Язык интерфейса русский, обращение на «ты». В коде и комментариях — английский, комментарии только «почему», без ссылок на номера задач.
- Токены только из `app/src/design/tokens.css` (копия `docs/design/2026-09-25-redesign/tokens.css`). Сырые hex-цвета в компонентах запрещены.
- Шрифты: Unbounded 600 (заголовки, вкладки, крупные числа), Onest 400/500/600 (всё остальное). Капс с разрядкой запрещён.
- Любая кнопка и чип `white-space: nowrap`. Касание не меньше 44×44.
- Анимируются только `transform` и `opacity`. При `prefers-reduced-motion: reduce` переходы мгновенные.
- Выпадающие `<select>` для частых действий запрещены: вкладки, сегменты, чипы, панели.
- Обе темы (светлая и тёмная) проверяются на каждом экране. Переключатель: «Светлая / Тёмная / Как в системе».
- Телефон 390×844 — основной размер. Десктоп от 1024px имеет свою раскладку (боковое меню 96px, 5 колонок, правая колонка от 1280px).
- Пока не завершён подпроект C, схему базы менять нельзя. Разрешено только добавлять необязательные колонки.
- Данные на макетах (Вадим, Лёша, Катя, числа) — примеры, в код не попадают.
- Коммиты маленькие, по одному на задачу или шаг, сообщения на английском в стиле репозитория (`feat: …`, `fix: …`, `docs: …`, `chore: …`).
- Выкатка: `master` → GitHub Actions → GitHub Pages. Прод не ломаем: v1 работает до конца C.

## Review Focus

Пять вещей, которые тестам задач легко пропустить, но которые больнее всего ударят по людям. У каждой есть тест в задаче-владельце.

1. **Правки, сделанные офлайн или во время синхронизации, не теряются** при переходе v1 → v2 и при миграции схемы (B). Тесты: очередь в `sync.ts` (A4), скрипт сверки миграции (B4).
2. **Приватные доски и скрытые тайтлы никогда не видны другим**, ни в одной соцфункции: лента, совпадения, полка друга, лидерборд, «У друзей». Тест: SQL-проверки на каждую RPC (D1–D8).
3. **Добавление с открытой клавиатурой на iPhone**: поле и первый результат видны без прокрутки (BL-25). Тест: e2e на эмуляции iPhone с уменьшенной видимой областью (C8).
4. **У тайтлов с частями статус не прыгает и ручной статус не теряется** после материализации производного статуса. Тесты: `derive.ts` (B5), скрипт миграции (B4).
5. **Две версии на одном устройстве не портят друг другу данные**: разные ключи `localStorage` (`bl2:`), разные scope сервис-воркеров. Тест: e2e с предзаполненным зеркалом v1 (A7).
